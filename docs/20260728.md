## 3. 在线安全特征定义

今日确认所有模型输入必须在 kernel 启动前可得。

核的输入输出语义：

| Kernel | 输入 | 输出 |
|---|---|---|
| GETRF | A | L、U |
| GESSM | A、L | X |
| TSTRF | A、U | X |
| SSSSM | A、L、U | A |

稀疏结构在计算前确定，因此可用于在线模型；运行时间、实际 memcpy 次数、
运行后统计和 CUDA event telemetry 不得作为特征。

特征 schema v2 包括：

- block size、实际 block rows/cols；
- 各输入输出 NNZ 与 density；
- MAC、division 和 `operation_count_v2`；
- 行列 NNZ 均值、最大值、CV、空行/空列比例；
- work mean/max/CV、active work fraction；
- value/index/pointer/output/workspace/base bytes 估计；
- index/value byte ratio、reuse factor；
- block CSC locality；
- derived CSR locality（辅助实现视图）；
- active rows/cols；
- SSSSM 10 个 workload bins、非空 bin 数、最大 bin 比例和 sparse launch 数。

GETRF 进一步增加了与实际 CUDA 代码一致的运行前 launch 特征：

- adaptive launch policy；
- grid blocks；
- block threads；
- warps/block；
- rows/block；
- grid blocks/SM；
- minimum scheduling waves；
- thread slots；
- NNZ/thread slot。

历史 profiling 平台是 `NVIDIA H100 80GB HBM3`，按 132 SM 计算：

```text
minimum_waves = ceil(grid_blocks / 132)
```

该值是调度波数下界，不等同于 occupancy。

按时间：

| Actual time | Samples | MAPE |
|---|---:|---:|
| <0.03 ms | 6,384 | 69.84% |
| 0.03–0.05 ms | 4,067 | 47.36% |
| 0.05–0.1 ms | 7,646 | 38.83% |
| 0.1–0.3 ms | 14,138 | 32.82% |
| 0.3–1 ms | 13,294 | 25.44% |
| 1–3 ms | 5,019 | 20.80% |
| 3–10 ms | 956 | 14.77% |
| 10–30 ms | 168 | 7.28% |

小于 0.1 ms 的样本占 35.0%，贡献总体 MAPE 的 50.35%。

代码层面，sparse SSSSM 不是一个固定 kernel，而是最多 10 个 bin 对应的
thread/warp/block-level kernels。每个非空 bin 产生一次 launch。目前虽有
bin row count、非空 bin 数和 launch count，但缺少每个 bin 的：

- grid blocks；
- block threads；
- warps；
- blocks/SM；
- minimum waves；
- tail utilization；
- operation/byte estimate；
- kernel-family-specific launch cost。

建议下一阶段离线生成上述逐 bin launch 特征，并建立：

```text
T_sparse =
sum_i(
  launch_cost_i * I(bin_i nonempty)
  + alpha_i * bin_i_operations
  + beta_i * bin_i_bytes
  + gamma_i * bin_i_waves
)
+ residual(pre-kernel features)
```

默认执行策略在 `density(A) >= 0.001` 时选择 dense，否则选择 sparse。当前
forced-sparse 测试包含大量默认策略不会选择 sparse 的样本；正式报告应同时给出：

1. 全部 forced-sparse；
2. 默认策略选择 sparse 的子集；
3. sparse 实测快于 dense 的子集。

## 10. 为什么 GESSM/TSTRF 更可靠

GESSM/TSTRF 的模型较可靠，主要原因：

1. 执行路径比 SSSSM-sparse 更统一，性能函数更连续。
2. operation count、bytes、NNZ、row/column irregularity 与实际 CUDA 循环
   对应更直接。
3. 每个逻辑任务有两次测量，中位数降低短时抖动。
4. 不存在最多 10 种异构 bin kernel 组合的离散切换。

## 12. Block size 与外推边界

block size 是所有 kernel 的重要性能因素，但实际模型还依赖：

- actual block rows/cols；
- NNZ；
- operations；
- bytes；
- irregularity；
- active parallelism；
- launch/grid/waves。

当前 profiling 最大 block size 为 16384。HGB/EBM 属于树模型，不能可靠外推到
32768 或更大；超范围输入通常落入训练边界叶节点。

Roofline-residual 的显式 operations/bytes 基线具有更合理的增长趋势，但 residual
树模型仍未在大 block 上验证。因此：

- `block_size <= 16384`：当前已验证范围；
- `block_size > 16384`：允许输出预测，但必须标记 OOD/low confidence；
- 若要在线选择更大块，应补充 24576、32768，资源允许时再补 49152/65536；
- 大块实验需特别记录 OOM、timeout、workspace 与真实非边界块覆盖。

## 14. 指标解释约定

- MAPE：绝对百分比误差均值，对极短任务非常敏感。
- MdAPE：绝对百分比误差中位数，受极端值影响较小。
- P95 APE：95% 样本的 APE 不超过该值，反映误差尾部。
- R2：解释整体方差的能力；大任务可主导 R2，因此高 R2 不保证短任务 MAPE 小。

正式报告不应只给 MAPE，至少同时给：

```text
MAPE + MdAPE + P95 APE + R2 + RMSE/MAE
```

并按 runtime regime、matrix、kernel variant 分层报告。

## 16. 当前结论

1. feature replay v2 与严格合并流程已建立，模型特征满足目标 kernel 启动前可得。
2. 重复标签必须先合并，再划分 train/test；否则会发生任务级数据泄漏。
3. 每矩阵内部 8:2 显著改善 GETRF、GESSM、TSTRF 和 SSSSM-dense，适合作为
   已覆盖矩阵上的在线决策评估。
4. 整矩阵 holdout 仍有价值，应作为未见矩阵外推补充，而不是删除。
5. SSSSM-sparse 是当前主要瓶颈，其问题集中于极短任务和未充分表达的逐 bin
   异构 launch 行为。
6. 当前模型对 block size >16384 没有经过验证，不能报告为可靠外推。
