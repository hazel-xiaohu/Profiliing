# 2026-07-31 工作日志

## 1. 今日目标

今天的工作集中在降低 `Partition` 相对规则分块 PanguLU 的 CPU 端额外开销：

- 使用 CPU 多线程优化混合分块 preprocessing；
- 并行构建可安全拆分的 symbolic 结构缓存和基本块摘要；
- 减少候选之间对 L/U 结构的重复扫描；
- 减少循环中的 `malloc/calloc/free` 和临时数组重复分配；
- 保持 `block_common->ptr[]` 接口、分块代价公式及 Greedy 决策语义不变；
- 为 `1/2/4/8` 线程的正式端到端对照实验确定矩阵集和计时指标。

## 2. CPU 多线程实现

主要修改文件：

```text
Partition/src/pangulu_partition_greedy_v1.h
Partition/src/pangulu_preprocess.h
Partition/src/pangulu_symbolic.h
```

### 2.1 线程控制

新增分块专用线程控制：

```bash
PANGULU_PARTITION_CPU_THREADS=<threads>
```

例如：

```bash
export PANGULU_PARTITION_CPU_THREADS=8
./test/PanguLU_output_matrices matrix.mtx
```

若不显式设置，程序按照工作量自适应选择线程数：小规模问题使用单线程，避免
OpenMP 团队创建和同步开销；较大问题默认最多使用 8 线程，同时不超过
OpenMP 可用线程数及实际工作项数量。

### 2.2 基本块结构摘要并行化

混合分块 Greedy 需要为每个基本块生成结构摘要。当前实现将各基本块摘要的构建
按基本块并行分配：

- 每个线程拥有独立的 lower/upper 临时结构数组；
- 每个线程只在初始化时分配一次 workspace；
- 同一线程处理多个基本块时复用 workspace；
- 并行阶段只写入对应的 `base_summary[i]`，避免数据竞争；
- prefix 摘要合并和 Greedy 前向搜索仍保持串行；
- audit 文件在并行计算结束后按固定顺序写出，避免多线程 FILE 写入竞争并保持结果可复现。

Greedy 搜索没有强行并行化，因为当前从前向后的合并决策依赖已经选定的前缀状态。

### 2.3 Preprocessing 并行化

`pangulu_preprocess.h` 中以下阶段改为基于 block row 的 OpenMP 并行：

- 标量行到 block row 的映射；
- L/U 每个块的 NNZ 计数；
- 块内 CSC column pointer 计数；
- 每个块的局部 prefix 构建；
- 块内 CSC row/value 填充。

并行所有权规则为：一个 block row 的全部输出单元由同一个线程处理。这样不需要
对每个计数使用 atomic，也不会出现多个线程同时更新同一块局部写指针的问题。

旧代码中的部分 OpenMP pragma 使用全局 `PANGU_OMP_NUM_THREADS`，但该值实际保持为
1，因此此前这些循环并没有获得有效 CPU 并行加速。本次新增的分块专用线程控制
不依赖该固定值。

## 3. 重复扫描和内存分配优化

### 3.1 Reusable workspace

基本块摘要不再为每个基本块重复申请和释放完整临时数组，而是每个 OpenMP 线程
持有一套私有 workspace，并在该线程的所有基本块之间复用。后续 Greedy 候选搜索
继续使用已有的单套可复用 workspace。

这降低了：

- `malloc/calloc/free` 调用次数；
- 大数组反复初始化的成本；
- 多线程下 allocator 锁竞争和内存碎片风险。

### 3.2 FLOP 扫描复用

原 preprocessing 会再次全量扫描 `calculate_sum[]`，并为此申请 `tmp_index`。
现在 symbolic 阶段完成后直接保存全局 FLOP：

```text
FLOP = 2 * calculate_sum[N]
```

preprocessing 复用该结果，删除重复全矩阵扫描及对应的 `tmp_index` 分配。FLOP 的
统计定义没有改变，因此不会影响已有性能公式和实验口径。

### 3.3 当前并行边界

需要区分两类 symbolic 工作：

1. 已并行化：由已经构造的结构缓存生成基本块摘要，以及 preprocessing 中的块结构缓存；
2. 仍串行：原始 symbolic elimination 和与消元顺序耦合的 L/U 结构生成。

原始 symbolic 构造存在消元依赖，不能简单添加 OpenMP pragma。若后续仍是主要瓶颈，
需要将其重新设计为依赖分析与结构填充两阶段算法。本次没有改变这部分语义，以优先
保证结构正确性。

## 5. 初步性能观察

### 5.1 小矩阵

`ACTIVSg10K` 强制使用 8 线程时，线程创建和同步成本可能超过并行收益。该现象说明
小问题必须保留自适应单线程路径，不能无条件使用最大线程数。

### 5.2 较大矩阵

`poisson3Db` 的一次初步对照中：

| 线程数 | Greedy build | Greedy search | Preprocessing | Pipeline |
|---:|---:|---:|---:|---:|
| 1 | 3.285 ms | 6.050 ms | 3.934 s | 7516.815 ms |
| 8 | 2.784 ms | 6.130 ms | 3.150 s | 6776.970 ms |

该次观察中 preprocessing 约下降 19.9%，pipeline 约下降 9.8%。但是两次进程曾有
执行重叠，会产生 CPU/GPU 资源干扰，因此这些数值只能证明优化具有潜力，不能作为
论文正式性能数据。正式结论必须来自串行执行、多次重复的受控实验。

## 6. 正式线程扩展实验设计

已核验当前方案级数据集：

```text
Partition/artifacts/scheme_nb_ranker_v2/combined_33_candidate_dataset.csv
```

其中包含 33 个唯一矩阵，33 个矩阵文件目前全部存在。计划对每个矩阵依次测试：

```text
threads = 1, 2, 4, 8
repeats = 3
```

总运行数为：

```text
33 matrices × 4 thread counts × 3 repeats = 396 runs
```

每次运行应保存原始日志，并提取：

- `symbolic_total_ms`；
- preprocessing time，统一换算为 ms；
- Greedy `build_ms`；
- Greedy `search_ms`；
- `pipeline_total_ms`；
- 外部 process wall time；
- return code、timeout、residual 和结构输出，用于识别无效样本。

正式实验必须满足：

- 同一时刻只运行一个矩阵，避免 CPU/GPU 资源重叠；
- 不并发运行不同线程配置；
- 每完成一次立即原子更新 CSV；
- 支持 `--resume`，中断后跳过已完成组合；
- 线程配置顺序最好按 repeat 做确定性随机化，降低温度和执行顺序偏差；
- 失败和 timeout 保留记录但不进入加速比统计；
- 使用三次成功运行的中位数作为主结果，同时报告离散程度。

主要比较指标：

```text
speedup_stage(t) = median_time(1 thread) / median_time(t threads)
```

同时报告：

- 各阶段绝对节省时间；
- preprocessing 在 pipeline 中的占比；
- Greedy build/search 在 pipeline 中的占比；
- 小、中、大矩阵的线程收益差异；
- 1/2/4/8 线程的几何平均 speedup；
- 结果不一致或 residual 异常的矩阵清单。

截至本日志保存时，正式 396 次实验的矩阵集和统计口径已确认，但批量运行尚未启动，
因此不能将初步 `poisson3Db` 数据当作正式线程扩展结论。

## 7. 当前结论与下一步

今天完成的是一版以正确性为优先的 CPU 并行化：preprocessing 的安全热点已经并行，
基本块结构摘要改为每线程 workspace 并行构建，重复 FLOP 扫描和部分重复分配已经删除。
1/8 线程下分块和结构结果一致。

下一步按 33 个正式矩阵运行 396 次受控测试。根据阶段计时结果再决定第二阶段优化方向：

- 若 preprocessing 仍占主导，继续并行剩余安全循环并优化 NUMA/首次触页；
- 若 symbolic elimination 占主导，评估两阶段并行 symbolic 的开发成本；
- 若 Greedy build 占主导，调整并行阈值和调度粒度；
- 若 search 占主导，则考虑候选批处理或保留串行但减少候选数；
- 若 pipeline 改善很小，则停止扩大 CPU 并行改造，避免工程复杂度超过端到端收益。
